# Phase 0：ASR 基准测试

## 目的

用同一批匿名、可重复的中文和中英混说文本，比较候选 ASR Provider 的真实延迟、识别质量和数据政策。`tests/fixtures/asr-corpus.json` 只包含合成测试文本，不包含真实用户录音。

## 语料构成

| 类别 | 数量 | 覆盖内容 |
|---|---:|---|
| `daily_cn` | 20 | 日常中文短句 |
| `long_cn` | 20 | 连贯中文段落（用于 30～90 秒录制） |
| `mixed_tech` | 20 | 中英混说和技术词 |
| `tokens` | 15 | 数字、日期、版本、URL、代码标识符 |
| `noise` | 15 | 键盘、风扇、办公室、人声和距离条件 |
| `repair` | 10 | 停顿、改口、自我修正和否定关系 |
| **合计** | **100** | |

`long_cn` 是文本基线，不把文字长度本身当作已达到 30～90 秒；实际录制时应按统一语速和停顿规则形成目标时长。噪声类别的 `condition` 只描述录制条件；实际录音时仍需使用同一条文本，并为每个 Provider 保持相同设备、距离和音量。

## 记录字段

每条样本至少记录以下字段：

```text
provider
sample_id
condition
first_partial_ms
final_result_ms
cer
wer
punctuation_ok
technical_token_ok
repair_relation_ok
request_failed
failure_reason
data_retention_note
```

- `first_partial_ms`：开始发送音频到首个临时结果的耗时；
- `final_result_ms`：停止说话到最终结果的耗时；
- `cer` / `wer`：分别计算中文字符错误率和按空格切分的词错误率；
- `technical_token_ok`：版本、URL、代码标识符、数字是否保持；
- `repair_relation_ok`：改口、否定和最终选择是否保持；
- 失败和超时必须单独统计，不能当作空字符串算准确。

## 统一执行规则

1. 每个 Provider 使用相同的 100 条参考文本和相同的录制顺序；
2. 首轮每条至少重复 3 次，报告中同时给出中位数和 P95；
3. 记录网络、设备、采样率、音量条件和 Provider 版本；
4. 关闭生成式整理，避免把 LLM 改写结果混入 ASR 评分；
5. 默认不保存原始音频。若为复核临时保存，必须显式标记、限定本地目录，并在复核后删除；
6. Provider 失败、限流、断网和取消都要保留错误原因，不用“识别质量差”笼统归类。

## 本地评测工具链（已建立）

评分口径已实现为可运行的本地工具，位于 `tests/asr-eval/`，详见 [`tests/asr-eval/README.md`](../tests/asr-eval/README.md)：

- `scoring.py`：CER/WER、高风险 Token（URL/版本/标识符/点分路径/数字）确定性比对、标点检查、中位数与 P95；
- `evaluate.py`：读入单 Provider 评测记录 JSON，输出汇总 JSON 与与本文对比表同构的 Markdown 报告；
- 失败与超时单独统计；`request_failed=false` 但结果为空按 `empty_hypothesis` 失败处理并警告；
- `repair_relation_ok` 为人工判断项，缺失按不通过计并警告，工具不自动补真；
- 未知样本、缺失样本、缺失时延、非法字段类型（布尔/Infinity 混入计时）均进入警告清单，不静默吞掉；
- 经对抗式审查修正（2026-09-03）：普通英文词不逐词强制（词边界在 CER 等价变换下不可靠，由 CER 兑底）；标识符/点分路径大小写敏感（对应产品约束 3）；URL 在去空白底板上匹配；数字边界只看相邻数字；存在性语义（出现 ≥1 次即算保留）；
- 44 项单元测试通过，并固化三条对抗不变量回归：ref==hyp 全过、CER 等价变体不误报、删除 Token 必报警（32/32 捕获）；全部使用显式标注的模拟数据；
- 默认输出不含识别正文，`--include-text` 仅限本地复核，产物不得提交；
- 同一 `sample_id` 的多次重复（每条 ≥3 次）逐条计入统计。
