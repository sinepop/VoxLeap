# Phase 0 / P0-09：产品原型访谈脚本

## 目的

用浏览器原型（`prototype/`，模拟识别）完成至少 **5 名目标用户**的关键任务访谈，记录误解点，验证信任机制与目标提示是否合格。访谈结果只用于修改 PRD 与交互规范，不作为任何功能"已验证"的依据。

## 用户画像与招募

- 优先：Vibe Coding 人群（每天在 Cursor/VS Code 里写中文注释、文档、commit message 的开发者），3 人；
- 次优：日常大量中文输入的办公用户（微信/飞书/Word），2 人；
- 排除：本项目组成员、已深度了解产品设计的熟人；
- 方式：远程屏幕共享或线下，各 30～40 分钟，征得同意后可记录（优先文字笔记，避免保存录音）。

## 前置准备

1. 本地起原型：

   ```bash
   cd <VoxLeap-repository>
   python3 -m http.server 4173 --directory prototype
   ```

2. 被试机器浏览器打开 <http://localhost:4173>；
3. 告知被试："这是一个语音输入的交互演示，识别是模拟的，请按平时习惯使用"；除演示按钮位置外不做操作指导。

## 任务清单（来自实施计划 §5.2）

按顺序执行，观察者只记录不提示：

| # | 任务 | 观察重点 | 通过判定 |
|---|---|---|---|
| T1 | 不使用 AI 完成一次输入（关闭生成式整理） | 能否找到"原文/关闭 AI"入口；是否误解为"完全不联网" | 无协助完成 |
| T2 | 使用轻整理并指出系统改动了什么 | 是否能对照原文发现改动；是否信任改动 | 能指出至少 1 处改动 |
| T3 | 发现一个字幕错误并在审阅阶段修正 | 是否知道错误可改、在哪里改 | 无协助完成修正 |
| T4 | 模拟 AI 失败后继续使用原文 | 失败提示出现后是否丢失内容、是否慌乱 | 原文可继续使用 |
| T5 | 口头回答："这段内容会被插到哪里？会自动发送吗？" | 目标提示与发送边界的理解 | 两个问题都答对 |

**T5 是信任机制的硬门槛**：任一被试答错，即判定当前目标提示设计不合格，必须回到交互规范修改，不能靠解释弥补。

## 记录模板

每名被试一份，访谈后 24 小时内整理：

```text
被试编号：V01（不记录真名）
画像：开发者 / 办公用户
日期与方式：

T1 完成：是/否  用时：    协助次数：
T2 改动识别：自发发现 / 提示后发现 / 未发现
T3 修正完成：是/否
T4 失败后行为：
T5 答案原话：
误解点（原话引用）：
意外用法：
主动提出的缺失功能：
原型的哪些部分让被试犹豫：
```

## 汇总口径

- 完成 5 名被试后统计：每项任务的无协助通过率、误解点去重列表、T5 错误数；
- 误解点按"交互问题 / 文案问题 / 认知预期问题"分类；
- 结论写入 `PROGRESS.md` 的 P0-09 小节，并回溯修改 `docs/01-PRD.md` 与 `docs/02-UX与视觉规范.md`；
- 访谈记录不提交真实个人信息，编号即可。
