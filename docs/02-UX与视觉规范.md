# 声跃 VoxLeap UX 与视觉规范

## 1. 产品形态先决策

声跃最终不是网页，也不是需要一直打开的桌面工作台。

正式形态是 **Windows 托盘常驻输入工具**：

- 空闲时没有常驻主窗口；
- 用户把光标放在任意受支持的输入框；
- 按住一个可自定义按键，屏幕底部浮出声纹和实时字幕；
- 松开按键后，在底部完成简短审阅；
- 确认后文字回到原输入框。

浏览器 `prototype/` 只验证浮层的比例、动效、信息层级和操作理解，不作为正式客户端技术栈。

## 2. 视觉方向：声纹玻璃

视觉主题从偏通用 AI 的“霓虹卡片”调整为 **声纹玻璃（Voice Glass）**。

关键词：

- 系统级；
- 通透；
- 安静；
- 有触感；
- 有一条属于声跃的连续声纹；
- 精致但不过度装饰。

参考高质量液态玻璃材质的光学规律，但不照搬任何系统组件。声跃自己的识别特征是：

1. **单线声纹**：实时输入不是常见的等高柱状音频条，而是连续、柔和、具有呼吸感的声纹带。
2. **脉冲声标**：正式 Logo 由五个上下长短不一、向前倾斜的纯色几何块组成，以蓝青双色形成节奏；不再使用背景虚线或心电波，避免装饰削弱识别。录音时方块只做轻微跃动，表达声音正在“跃”起来。
3. **克制用色**：Logo 固定使用蓝 `#0046F1` 与青 `#00E2F1`；界面声纹继续使用低饱和青色，暖色只作为小面积点缀，避免通用 AI 紫蓝渐变和红蓝对半背景。
4. **底部出现**：产品视觉只在用户需要时进入，不占据工作空间。

## 3. 明确避免的视觉模式

- 不把产品做成带侧边栏、顶部导航和数据面板的网页工作台。
- 不使用黑底、霓虹紫蓝、大面积光污染作为默认主题。
- 不堆叠多层圆角卡片、边框、分割线和状态框。
- 不使用 AI 星芒、机器人头像、魔法棒等泛化符号。
- 不让每个按钮都拥有描边和发光。
- 不用随机跳动的柱状波形冒充真实声音反馈。
- 不让动画比字幕更抢眼。

## 4. 唤起键设计

### 4.1 正式产品

全局按键必须可配置，提供“按住说话”和“按一下开始/再按一下结束”两种方式。

不建议默认占用左 `Ctrl`：它参与复制、粘贴、撤销等高频组合键，误触成本高。个人自用运行版已实现热键可选：右 `Ctrl` / 右 `Alt` / 右 `Shift` / `Caps Lock`，配合“按住说话”或“按一次开始、再按一次结束”两种触发方式；`Caps Lock` 作为热键时会被程序吞掉，不会切换大小写。鼠标侧键与完全自定义组合键仍是后续目标。

### 4.2 浏览器原型

原型使用 **右 `Ctrl`**：

- 按下：出现声纹并开始模拟转写；
- 持续按住：字幕更新；
- 松开：结束并进入审阅；
- `Esc`：取消。

页面同时提供鼠标长按入口，便于没有右 `Ctrl` 的键盘体验。

## 5. 界面层级

### 5.1 空闲

正式产品完全隐藏，只保留托盘状态。原型中的说明区只是教学辅助，不进入正式浮层。

### 5.2 实时输入浮层

屏幕底部中央出现一个宽约 `520px`、高约 `68px` 的玻璃胶囊。

组成：

- 左侧取消按钮；
- 中间连续声纹；
- 录音时间；
- 右侧按键状态“Ctrl / 松开完成”。

字幕位于胶囊上方，使用独立的小块玻璃承载，最多三行。它不是对话框，不遮挡大面积内容。

### 5.3 插入前审阅

松开后，底部胶囊自然扩展为宽约 `660px` 的审阅浮层，不跳到屏幕中央，不添加沉重遮罩。

审阅层包含：

- 目标位置：“写入「灵感草稿」之前”；
- `原文 / 润色 / 提纲` 三种结果；
- 可编辑文本；
- 对照原文；
- 重新录制、复制文字、写入光标处。

用户始终能看见背后的目标应用，保持“我还在原来的工作里”的连续感。

### 5.4 底部操作栏

三个动作使用同一组件家族和一致尺寸，不再使用两个无标签小圆按钮加一个深色 AI 胶囊：

- **重新录制**：麦克风与回转轨迹组合图标，同时显示“再说一遍”；
- **复制文字**：使用与重录相同尺寸的 21px 双页图标，同时显示“保留到剪贴板”；
- **写入光标处**：使用箭头进入文本光标的专属图标，并提示“不会自动发送”。

主要动作只用轻微青色玻璃区分，不使用黑青渐变、通用右箭头或过度发光。

### 5.5 完成

文字向下轻微收束，审阅层缩回并消失。只提示“已写入光标处”，不能写“已经发送”。

### 5.6 设置窗口

设置是从托盘或桌面快捷方式按需打开的普通 Windows 窗口，不是常驻主工作台。普通用户不应编辑 JSON 才能开始使用。

首版设置按“常用 / 高级”分层：

- 常用：已验证的服务预设、模型、遮罩 API Key、识别语言、自动输入和当前热键事实；
- 高级：Base URL、endpoint、热词、超时和录音上限；
- 已验证预设默认锁定服务地址，避免错误拼接；排障时可显式解锁，并可一键恢复官方预设；
- 切换供应商必须清空当前 Key，避免把一家服务的凭据发送给另一端点；
- 测试连接只发送明确标注的短静音样本，不采集麦克风；
- `401/403`、`404`、`400/422`、`429` 与网络错误必须给出不同原因和下一步；
- 官方文档入口必须与当前预设对应，不能只给一个泛化“请求失败”。

## 6. 字幕表现

用户在说话时必须知道系统听到了什么：

- 已确认文字：高对比实色；
- 仍可能修订的文字：降低不透明度；
- 低置信术语：点状下划线与暖色文字共同提示；
- 最终确认：文案变为“正在确认最后一句”；
- 不整段闪烁，不因单词修订导致字幕整体位移。

真实客户端声纹必须由麦克风音量或频谱驱动。浏览器原型的模拟声纹必须持续标注为模拟。

个人自用运行版当前没有逐词实时字幕，但识别等待期会显示 StepFun SSE `delta` 增量累积的实时文字条（尾部截断，最新内容优先）；它是进度提示，不是最终确认字幕，最终文字仍以 `transcript.text.done` 为准。

## 7. 文字整理命名

界面不使用一个含义模糊的“AI 开关”，改为结果导向的三种选择：

| 模式 | 含义 | 生成式整理 |
|---|---|---|
| 原文 | 保持转写原样 | 关闭 |
| 润色 | 去口头语、修正断句 | 开启 |
| 提纲 | 在不改变事实的前提下整理层次 | 开启 |

“原文”下方必须明确显示“保留口述”，并在状态说明中显示“不使用生成式文字整理”。原文始终保留，切换模式不能覆盖用户已经编辑的草稿。

## 8. 玻璃材质规则

玻璃感不是简单设置透明度，需要四层共同成立：

1. **背景折射感**：使用适度背景模糊和饱和度，而不是纯色半透明矩形。
2. **上沿反光**：顶部有极细、非均匀的高光，底部有轻微暗边。
3. **内部光场**：玻璃内部使用面积很小的柔光，不画完整矩形描边。
4. **环境阴影**：阴影宽、淡、分层，避免黑色硬投影。

Windows 11 优先使用系统材质和 WinUI Composition；不支持时采用性能可控的 Acrylic/半透明降级。Windows 10、远程桌面和“减少透明效果”开启时，必须保持可读性，不能依赖透明度才能识别边界。

运行版允许按交互职责使用两级材质，但必须形成明确规则：不抢焦点的录音、识别和完成提示使用紧凑深色 HUD；需要键盘编辑的审阅与设置窗口使用高可读浅色工作面。差异来自交互职责，不得在同一窗口内部随机翻转主题。瞬时 HUD 统一 16px 圆角，活动窗口使用 Windows 标准窗体与一致的内容间距。

## 9. 色彩与字体

建议起始色彩：

| 用途 | 建议 |
|---|---|
| 主文字 | 深墨灰 `#182126` |
| 品牌青 | `#207785` |
| 深品牌青 | `#155563` |
| 声纹暖端 | 珊瑚色 `#E97D6D` |
| 成功提示 | 柔和绿色 `#4FA67F` |
| 玻璃底 | 依据背景自适应的乳白半透明材质 |

不设置固定的“AI 紫”。AI 整理通过文字状态和交互说明表达，而不是靠紫色发光。背景采用珍珠白底上的薄荷、淡紫、香槟和水绿色极光场，颜色彼此交叠缓慢漂移，不能形成一边蓝、一边红的机械分区。

普通 UI 使用系统无衬线字体；用户正文和字幕可使用克制的系统衬线字体增强书写感，但必须保障中英文混排和低字号清晰度。

## 10. 动画规范

- 浮层出现：`180～260ms`，从底部轻微上浮和展开。
- 声纹：由真实输入连续驱动，不使用固定循环模板。
- 松开确认：能量在 `300～500ms` 内收束为细线。
- 胶囊展开为审阅层：`240～320ms`。
- 完成消失：不超过 `240ms`。
- 低对比循环动画不超过两个；禁止高频闪动。
- 开启系统“减少动态效果”后，用静态声纹和透明度变化替代位移、缩放和循环脉冲。

## 11. 可用性与无障碍

- 所有状态有可读文字，不只依赖玻璃、颜色或声纹。
- 浮层必须在明亮、深色和复杂桌面背景上保持对比度。
- 支持系统 DPI、文字缩放和多显示器。
- 200% 缩放时核心操作仍可见。
- 所有动作可用键盘操作。
- 动画、透明效果和提示音均可降低或关闭。
- 浮层不能抢走正在录音的目标输入框焦点。

## 12. 当前原型验证目标

新版原型验证：

1. 用户是否明确知道最终产品不是网页；
2. 用户是否理解右 `Ctrl` 是“按住说、松开审阅”；
3. 底部声纹是否比仪表盘式界面更像系统输入法；
4. 玻璃材质是否精致但不影响字幕阅读；
5. “原文 / 润色 / 提纲”是否能清楚表达 AI 可关闭；
6. 审阅层是否保持了与原目标应用的连续感。

原型不验证真实麦克风、ASR、全局快捷键、焦点恢复和跨应用文字注入。

当前个人自用运行版是正式规范的功能降级实现：录音态采用红色语义录音点、秒级时间码和五块品牌声波；松开后整段转写，暂不提供实时字幕和三种 AI 整理结果。`src/app-v0/README.md` 是运行版事实来源，本规范中未实现的项目继续作为产品级目标，不得标记为已完成。
