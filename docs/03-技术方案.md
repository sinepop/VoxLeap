# 声跃 VoxLeap Windows MVP 技术方案

## 1. 结论摘要

首版采用 **Windows 常驻桌面应用**，而不是立即注册为传统 IME：

- C# / .NET 8
- WinUI 3 + Windows App SDK
- WASAPI 音频采集
- 可替换的流式 ASR Provider
- 可替换的文本整理 Provider
- UI Automation 只用于识别目标控件和敏感状态
- Unicode `SendInput` 为短文本主路径，受控剪贴板粘贴为长文本回退

该方案优先验证最危险的三件事：目标焦点保持、主流应用注入兼容性、真实流式 ASR 延迟。Windows TSF、离线模型和跨平台客户端推迟到 MVP 之后。

## 2. 系统边界

```text
┌──────────────────────── 声跃客户端 ────────────────────────┐
│ GlobalHotkey / Tray / Settings                              │
│          ↓                                                   │
│ TargetTracker → SessionStateMachine → Overlay / Review       │
│                              ↓                               │
│ AudioCapture → VAD → ASR Provider → TranscriptAssembler      │
│                              ↓                               │
│                    Optional Polish Provider                  │
│                              ↓                               │
│             DraftStore → TargetValidator → TextInjector      │
└──────────────────────────────────────────────────────────────┘
                  ↓ TLS                         ↓ Windows APIs
            ASR / LLM 服务                  目标桌面应用
```

MVP 可先单进程实现，但领域层、平台层和供应商层必须通过接口隔离，避免 UI 直接调用网络或 Windows 注入 API。

## 3. 建议解决方案结构

```text
src/
  VoxLeap.App/                 # WinUI 窗口、托盘、依赖注入、生命周期
  VoxLeap.Core/                # 会话状态机、领域模型、文本版本管理
  VoxLeap.Platform.Windows/    # 热键、音频、焦点、UIA、注入、系统安全存储
  VoxLeap.Providers/           # ASR 与 AI 整理适配器
  VoxLeap.Infrastructure/      # 配置、SQLite/文件存储、网络、遥测接口
tests/
  VoxLeap.Core.Tests/
  VoxLeap.Platform.Tests/
  VoxLeap.IntegrationTests/
```

浏览器 `prototype/` 与正式客户端隔离，不复用为生产 UI，也不代表已选择 Web 技术栈。

## 4. 核心领域模型

```csharp
record TargetContext(
    nint WindowHandle,
    int ProcessId,
    string ProcessName,
    string? ControlType,
    bool IsPassword,
    DateTimeOffset CapturedAt);

record TranscriptVersion(
    string OriginalTranscript,
    string? PolishedTranscript,
    string EditableDraft,
    ResultMode Mode,
    bool IsUserEdited);

enum SessionState
{
    Idle, Listening, Finalizing, Review,
    Polishing, Inserting, Completed,
    Cancelled, RecoverableError
}
```

必须由状态机控制副作用：

- 只有 `Listening` 可以接收音频帧；
- 只有最终原文生成后才能请求 AI；
- `ResultMode.Original` 不得创建 AI 请求；
- 只有 `Review` 可以发起注入；
- 注入失败返回 `Review` 并保留草稿。

## 5. 目标窗口与焦点

### 5.1 捕获

用户唤起时保存：

- 前台窗口句柄和进程；
- UI Automation 焦点元素的类型与 `IsPassword`；
- 可用于重新定位的有限特征；
- 当前时间和显示器信息。

不默认读取输入框正文或周围文本。

### 5.2 监听悬浮层

监听窗口采用无激活策略，避免夺走目标输入焦点。需要验证：

- 多显示器与不同 DPI；
- 全屏窗口；
- 光标附近空间不足时的位置回退；
- Electron、Chromium、原生 Win32 和 UWP/WinUI 控件。

### 5.3 审阅卡片

审阅需要接收键盘输入，因此会获得焦点。进入审阅前保留 `TargetContext`；注入前：

1. 检查原窗口仍存在且进程匹配；
2. 检查用户是否切换目标；
3. 恢复目标窗口与控件焦点；
4. 再次确认不是密码控件；
5. 执行注入。

目标不确定时停止，不猜测新的输入框。

## 6. 文本注入策略

### 6.1 MVP 顺序

1. **短文本**：使用 Unicode `SendInput`，避免依赖键盘布局。
2. **长文本或多行文本**：写入带自有标记的临时剪贴板内容，发送粘贴快捷键。
3. **失败回退**：保留审阅稿并提供显式复制。

### 6.2 剪贴板安全

- 注入前快照原剪贴板，但不得将其中内容写入日志。
- 为应用写入的剪贴板版本生成进程内标记和序列号。
- 粘贴完成后，仅当剪贴板仍是声跃写入的版本时恢复快照。
- 若其他程序或用户更新了剪贴板，不进行恢复，避免覆盖新内容。
- 大对象和无法序列化的剪贴板格式需要设定上限；无法安全恢复时提前提示。

### 6.3 已知边界

- 普通权限进程不能可靠注入高完整性管理员窗口。
- 安全桌面、部分游戏、远程桌面和受保护应用可能拒绝注入。
- `SendInput` 并不等价于完整 IME；复杂组合输入和候选体验需后续 TSF 支持。
- 不自动提权，不绕过系统安全边界。

## 7. 音频与流式 ASR

### 7.1 音频链路

- WASAPI 采集系统默认或用户选择的麦克风。
- 内部统一为供应商支持的单声道 PCM 格式，例如 16kHz / 16-bit；实际参数由基准测试决定。
- 使用 VAD 做起止点检测、静音提示和无效音频抑制。
- 内存中使用有界环形缓冲；会话结束或取消后及时清零并释放。
- MVP 默认不将原始音频写入磁盘。

### 7.2 Provider 接口

```csharp
interface IStreamingAsrProvider
{
    Task<IAsrSession> StartAsync(AsrOptions options, CancellationToken ct);
}

interface IAsrSession : IAsyncDisposable
{
    ValueTask SendAudioAsync(ReadOnlyMemory<byte> frame, CancellationToken ct);
    IAsyncEnumerable<AsrEvent> ReadEventsAsync(CancellationToken ct);
    Task CompleteAsync(CancellationToken ct);
}
```

`AsrEvent` 至少区分：

- `PartialUpdated`：可被后续覆盖；
- `SegmentFinalized`：片段稳定；
- `SessionCompleted`：整段最终文本；
- `ProviderWarning` / `ProviderError`。

`TranscriptAssembler` 使用片段 ID 和修订号合并，不通过字符串简单追加，避免流式修订导致重复文字。

### 7.3 供应商基准

在锁定供应商前，用相同的匿名测试语料对比：

- 普通话、轻口音和中英混说；
- Cursor、React、TypeScript、WebSocket 等技术词；
- 安静、键盘声和普通办公室噪声；
- 首字延迟、最终延迟、字错率、断句质量、价格和数据保留政策。

不要只根据官网指标做决定。

## 8. AI 整理服务

### 8.1 请求约束

- 用户明确选择 AI 模式后才发起。
- 将转写内容作为数据字段发送，不把其中指令拼接为系统指令。
- 系统约束要求保留数字、否定、专有名词、代码标识符、路径、URL 和信息完整性。
- 设置严格超时和取消；失败时原文立即可用。

建议返回结构化结果：

```json
{
  "mode": "light",
  "text": "整理后的正文",
  "warnings": [
    { "type": "uncertain_term", "source": "疑似术语", "message": "请确认专有名词" }
  ]
}
```

客户端验证：空结果、异常扩写、长度激增、数字和 URL 差异。验证失败时标记警告或拒绝自动采用，不能把“模型成功返回”视为“语义安全”。

### 8.2 文本版本

至少保留四个会话内版本：

- 不可变 `OriginalTranscript`；
- 可选 `PolishedTranscript`；
- 当前 `EditableDraft`；
- 最近一次成功注入的 `InsertedText` 摘要或哈希。

默认会话结束后从内存清理；只有用户开启历史或崩溃恢复时才加密落盘。

## 9. 本地存储与凭据

- 普通设置：本地配置文件或 SQLite。
- 凭据：Windows Credential Manager 或 DPAPI 保护。
- 草稿恢复：独立开关，使用 DPAPI 加密并设置自动过期。
- 历史记录：默认关闭；用户可清空、设定保留期。
- 日志：记录状态、耗时、供应商错误码和内容长度，不记录正文、音频、剪贴板内容或凭据。

## 10. 网络可靠性

- 所有请求支持取消和总超时。
- ASR 断线后是否续传取决于供应商能力；不能续传时保留已确认片段。
- AI 请求可安全重试一次，但需使用会话 ID 防止重复计费和结果覆盖。
- 代理、证书错误和离线状态提供明确提示。
- Provider 服务地址和密钥不能硬编码到仓库。

## 11. 测试策略

### 11.1 单元测试

- 会话状态机的合法与非法转换；
- 流式片段修订、去重和最终合并；
- 原文不可变与多模式草稿切换；
- AI 关闭时零整理请求；
- 数字、URL、代码标识符变化检测；
- 剪贴板恢复条件。

### 11.2 集成测试

- 模拟 ASR 的延迟、乱序、重复和断线事件；
- 模拟 AI 超时、空响应和异常扩写；
- 测试目标窗口消失、切换和权限不匹配；
- 中英文、Emoji、换行和长文本注入。

### 11.3 手工兼容测试

每个目标应用记录：版本、控件类型、短文本、长文本、多行、撤销、DPI、管理员权限和结果。未运行的项目标记“未验证”，不能标记“支持”。

## 12. Phase 0 必做技术实验

1. **焦点与注入实验**：在六个首批应用验证捕获、无激活悬浮、恢复焦点和两种注入路径。
2. **ASR 烘焙测试**：至少 100 条匿名语料，对比两到三个可商用 Provider。
3. **窗口性能实验**：透明窗口、实时波形和字幕修订在 60 FPS 下的 CPU/GPU 占用。
4. **剪贴板竞争实验**：粘贴期间用户或剪贴板管理器更新内容时不覆盖新值。
5. **敏感输入实验**：密码框、安全桌面和高权限窗口安全失败。

完成这些实验后再锁定 Provider、默认快捷键、文本长度阈值和正式工程排期。
