# 声跃 VoxLeap 当前设计对抗式审查

- 日期：2026-09-04
- 审查对象：`src/app-v0/` 当前 Windows WinForms 运行版
- 非审查对象：`prototype/` 旧浏览器演示页
- 方法：taste skill + 视觉、产品 UX、Windows 架构安全三路独立审查，随后由主线裁决、隔离写入、fresh-context 挑战复核

## 设计判断

这是面向 Windows 日常输入用户的系统级悬浮工具，不是营销页或常驻工作台。目标语言是克制、低打扰、可恢复的系统工具。

审查参数：

- `DESIGN_VARIANCE: 5`
- `MOTION_INTENSITY: 5`
- `VISUAL_DENSITY: 4`

## 第一性原理

1. 用户要完成的是“可靠地把话变成当前输入框里的文字”，不是学习 API 配置格式。
2. 配置错误必须被定位为可行动的原因，不能统一显示成“连接失败”。
3. 已验证服务使用安全默认值，同时保留受警告保护的排障出口。
4. 密钥不能因为界面更易用而变得更不安全。
5. 桌面工具平时保持隐藏；设置是按需窗口，不演变成网页式主工作台。
6. 视觉差异必须来自交互职责，而不是随机换肤。

## 已发现并解决

| 优先级 | 问题 | 根因 | 处理 |
|---|---|---|---|
| P0 | 快捷方式图标像附在透明玻璃底板上 | ICO 每一帧的背景最小 alpha 约为 5%-7%，整张方形画布都参与合成 | 重新导出 16/24/32/48/64/128px 真透明 ICO；背景 alpha 为 0，仅保留五块 Logo；重建 exe、快捷方式并刷新图标缓存 |
| P0 | 普通用户只能编辑 `settings.json` | 把内部配置格式当成用户界面 | 新增“常用 / 高级”可视化设置窗口；托盘和桌面快捷方式均可打开 |
| P0 | API Key 明文保存 | 旧版直接写入 JSON | 新保存使用 Windows DPAPI CurrentUser；启动时自动迁移旧明文并删除明文字段；日志不记录 Key |
| P0 | 404 无法判断，容易反复改 Key | 没有区分鉴权、路径、协议、额度与网络错误 | 新增静音连接测试和分类诊断：401/403、404、400/422、429、网络、2xx 响应结构不兼容分别说明 |
| P1 | StepFun 订阅入口容易与开放平台路径混用 | “OpenAI-compatible”被错误理解成所有路径和请求体都通用 | StepFun SSE 作为已验证预设，默认锁定官方 Base URL 与 endpoint；可恢复官方预设，也可在高级页显式解锁排障 |
| P1 | 切换供应商可能把原 Key 发给新端点 | 服务参数和秘密没有隔离意识 | 切换服务类型立即清空 Key，要求输入该服务自己的凭据 |
| P1 | 配置保存后必须重启 | 运行态没有配置重载 | 设置窗口保存后立即更新内存；外部 JSON 变更在空闲时自动重载 |
| P1 | 文档描述与运行态不一致 | 浏览器原型、早期浅色玻璃和当前深色 HUD 混写 | 明确 `src/app-v0/README.md` 为运行版事实来源；UX 规范标注个人版降级边界和两级材质规则 |

## 对审查意见的裁决

### 接受

- 设置入口、密钥安全、404 诊断和文档漂移属于真实阻断，已优先修复。
- 高级字段不能全部堆给普通用户，已拆为“常用 / 高级”。
- 远程 API 必须使用 HTTPS；仅本机回环地址允许 HTTP。
- 配置写入保留上一次成功备份，主配置异常时尝试恢复。

### 部分接受

- “深色录音 HUD + 浅色审阅/设置窗口”不直接判为主题错误。前者是不抢焦点的瞬时状态，后者是需要键盘编辑的活动工作面。已把它固化为职责规则；同一窗口内部仍禁止随机翻转。
- 五块品牌图形保持不变，但不再加入后置虚线或玻璃底板。小尺寸识别优先依靠纯色剪影。

### 暂不实施

- 不在客户端自动抓取任意网页并猜测供应商配置。文档结构、鉴权和协议可能变化，自动猜测会把 404 变成更隐蔽的误配置。
- 不把所有声称 OpenAI-compatible 的服务列为可用供应商。只有真实验证请求体、鉴权、模型与响应结构后才能进入正式预设。

## 官方证据

2026-09-04 读取 StepFun 官方文档：

- Step Plan 语音接入：<https://platform.stepfun.com/docs/zh/step-plan/integrations/audio-api>
- StepAudio 2.5 ASR：<https://platform.stepfun.com/docs/zh/guides/models/stepaudio-2.5-asr>
- Step Plan 当前 ASR 限制：只支持 HTTP + SSE
- 已验证完整地址：`POST https://api.stepfun.com/step_plan/v1/audio/asr/sse`
- 请求协议：JSON + base64 PCM，`pcm_s16le / 16000Hz / 16bit / mono`
- 响应协议：SSE，`transcript.text.delta` 到 `transcript.text.done`

这解释了 OpenLess 当时的 404：即使界面允许填路径，只要客户端仍按 multipart `/audio/transcriptions` 请求，填入 Step Plan SSE 地址也不会兼容。

## 第二轮（2026-09-04）：热键、取消、字幕与草稿保护

依据用户指定的两个子代理通道（tokenrhythm/deepseek-v4-flash-0731、weixin-miniapp/Deepseek-v4-flash）执行双路终审，主线集成。

### 已实现

- **转写中可取消**：识别等待期按 `Esc` 终止请求（`AsrSession.Abort` + 2 秒看门狗兑底），提示“已取消，文字未保留”，不误报识别失败。
- **识别中实时字幕**：busy HUD 实时显示 StepFun SSE `delta` 累积文字（尾部截断、最新优先）；不采集额外数据。
- **热键可配置**：右 Ctrl / 右 Alt / 右 Shift / Caps Lock 四选一；“按住说话”或“按一次开始/再按一次结束”两种触发方式；Caps Lock 被吞掉不切换大小写；托盘文案随配置更新；旧配置缺字段时默认右 Ctrl + 按住。
- **审阅放弃保护**：内容已改动且未写入时，关闭前确认“确定放弃吗”，默认焦点在“否”。

### 主线修复（写入角色产出后）

- 修饰键判定改为对侧特定 VK（聚合键取反会在同时按住对侧同键时误放行；RMenu 分支改查右 Ctrl 避免 AltGr 布局下热键永远无法触发）。
- 取消以 session 标志统一判定（`Abort` 打断读流可能抛任意异常，不只 WebException）。
- `_hotkeyWasDown` 在取消/完成回 Idle 时强制复位（keyup 在安全桌面等场景可能丢失，锁存卡死会让热键永久失灵）。
- `_busy` 标志阻止迟到的字幕封送在浮层退场后重改尺寸。
- 复制失败路径也置 `_finished`，避免误弹放弃确认。

### 验证边界

- mcs 编译与 SettingsCoreTest 21+ 项、VoxleapCoreTest 21 项全部通过；Windows csc 构建与运行验证见 PROGRESS 同日记录。
- 真实按键路径（四种热键、toggle 模式、Esc 取消、delta 字幕观感）需用户实机反馈，未自动触发任何 ASR 请求。

## 本轮验收口径

- 普通用户不编辑 JSON 也能完成 StepFun 配置。
- StepFun 官方预设不会默认拼出错误的订阅路径。
- 测试连接不采集麦克风，只发送明确标注的短静音样本。
- 404 不再被误导为 Key 错误。
- API Key 不再以明文写回配置。
- 快捷方式图标透明区域 alpha 为 0，桌面只显示 Logo 图形。
