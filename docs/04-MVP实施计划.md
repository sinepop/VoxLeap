# 声跃 VoxLeap MVP 实施计划

## 1. 交付目标

交付一个可供小范围真实用户日常使用的 Windows 付费测试版，完整跑通：

```text
目标输入框 → 快捷键说话 → 实时字幕 → 最终原文
→ 可选 AI 整理 → 审阅修改 → 写回目标输入框
```

测试版不以“功能数量”为完成标准，而以低延迟、原文不丢失和目标应用注入稳定为发布门槛。

## 2. 阶段与产物

以下时间是假设两名全职开发加一名兼职设计/测试的粗略估算，需在 Phase 0 后重排。

### Phase 0：风险验证（约 2 周）

**产物**

- 六个首批目标应用的注入兼容性报告；
- ASR 匿名语料、评分方法和供应商对比；
- WinUI 透明悬浮层性能样机；
- 默认快捷键候选与冲突测试；
- 更新后的技术决策记录。

**退出条件**

- 至少一种注入路径在六个应用的普通输入场景可用；
- 至少一个 ASR 方案达到延迟底线；
- 已确认密码框、切窗和高权限窗口能安全失败；
- 云服务成本有可计算的单分钟模型。

### Phase 1：核心闭环（约 3 周）

**工作包**

- `E01` 应用生命周期、托盘、单实例与设置框架；
- `E02` 全局快捷键和目标捕获；
- `E03` WASAPI 音频采集、设备切换、VAD；
- `E04` 流式 ASR Provider 和字幕合并；
- `E05` 无激活监听胶囊；
- `E06` 最终原文审阅卡片；
- `E07` Unicode 与剪贴板注入；
- `E08` 会话内草稿恢复和基础错误处理。

**退出条件**

AI 完全关闭时，用户可在首批应用稳定完成原文语音输入。

### Phase 2：AI 整理与信任机制（约 2 周）

**工作包**

- `E09` 原文 / 轻整理 / 结构化模式；
- `E10` 整理 Provider、超时与取消；
- `E11` 原文不可变、多模式草稿和差异展示；
- `E12` 数字、URL、代码标识符变化警告；
- `E13` Vibe Coding 实验预设；
- `E14` AI 用量与隐私提示。

**退出条件**

AI 故障不影响原文输入；用户能明确判断 AI 是否介入并恢复原文。

### Phase 3：封闭测试与加固（约 3 周）

**工作包**

- `E15` 六个目标应用的自动/手工回归矩阵；
- `E16` 多显示器、DPI、休眠恢复和设备热插拔；
- `E17` 代理、弱网、断网、服务限流；
- `E18` 安装、签名、自动更新和卸载清理；
- `E19` 非正文遥测、崩溃报告和隐私开关；
- `E20` 无障碍、减少动态效果和性能优化；
- `E21` 新手引导、权限说明和问题诊断包。

**退出条件**

达到第 6 节发布门槛，并由真实测试用户完成至少一周试用。

## 3. Phase 0 任务拆分

| ID | 任务 | 验收结果 |
|---|---|---|
| P0-01 | 建立最小 WinUI 3 样机 | 托盘、全局热键、透明无激活窗口可运行 |
| P0-02 | 目标上下文探针 | 能记录窗口/进程/控件类型，密码框只返回敏感标记 |
| P0-03 | 短文本 Unicode 注入 | 六个目标应用逐项记录真实结果 |
| P0-04 | 长文本剪贴板注入 | 多行、中文、Emoji 可测，且不覆盖竞争写入 |
| P0-05 | ASR 测试语料 | 100 条匿名、覆盖中英混说和噪声的可重复语料 |
| P0-06 | ASR Provider 对比 | 延迟、错误率、价格、协议、保留政策均有记录 |
| P0-07 | 波形与字幕性能样机 | 60 FPS 目标下记录 CPU/GPU，不凭观感宣称通过 |
| P0-08 | 敏感与权限边界 | 密码框、高权限窗口、切窗均安全失败 |
| P0-09 | 产品原型访谈 | 至少 5 名目标用户完成关键任务并记录误解点 |
| P0-10 | 架构复盘 | 根据实验结果更新 PRD、技术方案和排期 |

## 4. MVP 优先级

### P0：缺失即不能发布

- 全局唤起和录音反馈；
- 流式字幕和最终原文；
- 原文模式不调用生成式 AI；
- 审阅、编辑、复制和注入；
- 目标验证和密码框保护；
- 网络/AI 故障时原文可用；
- 六个首批应用兼容测试；
- 默认不保存音频和正文日志。

### P1：进入公开测试前完成

- 轻整理、结构化和差异展示；
- 麦克风与快捷键设置；
- 多显示器、DPI 和减少动态效果；
- 安装签名、更新与诊断；
- Vibe Coding 预设；
- 非正文质量指标。

### P2：不阻塞 MVP

- 本地离线 ASR；
- 完整历史记录和跨设备同步；
- 自定义词典和应用级风格；
- Windows TSF 内核；
- macOS 客户端；
- 团队术语库和私有部署。

## 5. 测试语料与用户测试

### 5.1 ASR 语料类别

- 20 条日常中文短句；
- 20 条 30～90 秒长段落；
- 20 条中英混说技术需求；
- 15 条包含数字、日期、版本号和 URL；
- 15 条带键盘声、风扇声和办公室环境声；
- 10 条停顿、改口和自我修正。

不得使用真实客户机密或未经授权的录音。

### 5.2 原型访谈任务

1. 不使用 AI 完成一次输入；
2. 使用轻整理并指出系统改动；
3. 发现一个字幕错误并在审阅阶段修正；
4. 模拟 AI 失败后继续使用原文；
5. 说出“这段内容会被插到哪里”和“是否会自动发送”。

如果用户不能准确回答第 5 项，说明信任与目标提示仍不合格。

## 6. 发布门槛

以下指标必须来自真实 Windows 客户端，不来自浏览器原型：

- 六个首批应用普通输入场景注入成功率 ≥ 99%；
- 良好网络下首条临时字幕 P95 ≤ 600ms；
- 停止说话至最终原文 P95 ≤ 1.5s；
- 300 汉字内 AI 整理 P95 ≤ 3s，且超时可即时回原文；
- AI 关闭场景的生成式服务请求数为 0；
- 密码框误启动和误注入为 0；
- 目标窗口变化后的静默误注入为 0；
- 阻断级崩溃和原文丢失问题为 0；
- 安装、升级、退出和卸载流程均通过测试。

## 7. 主要风险

| 风险 | 影响 | 缓解方式 |
|---|---|---|
| 不同应用注入行为不一致 | 核心闭环失败 | Phase 0 先测；双路径注入；失败保留草稿 |
| 云端 ASR 延迟或中文技术词差 | 体验不可信 | 统一语料烘焙；Provider 可替换；个人词典后续增强 |
| AI 改变原意 | 用户失去信任 | 原文不可变；差异；关键 token 检查；默认轻整理 |
| 悬浮层抢焦点 | 内容进入错误位置 | 监听层无激活；审阅后重新验证目标 |
| 剪贴板覆盖用户内容 | 数据损失 | 序列号/标记校验；竞争更新时不恢复 |
| 云服务成本不可控 | 商业模式失效 | 统计每分钟成本；额度与 BYOK/本地模式预案 |
| 视觉动画消耗资源 | 影响办公与续航 | 性能预算；降级；减少动态效果 |
| 用户误以为“关闭 AI”也不联网 | 隐私误解 | 区分 ASR 和生成式整理，明确供应商与数据路径 |

## 8. 首轮待决策项

只有完成相应实验后再决定：

1. 默认全局快捷键；
2. 云端 ASR 供应商及备用供应商；
3. 轻整理和结构化使用的模型与成本上限；
4. `SendInput` 与剪贴板切换的文本长度阈值；
5. 是否在测试版启用本地草稿恢复；
6. 是否将 Vibe Coding 作为默认模式或实验功能；
7. 首轮付费模式和免费额度。
